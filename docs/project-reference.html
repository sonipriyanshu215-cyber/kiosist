Overview

What the site is, in one paragraph, plus the two architectural decisions that shape everything below.

Kiosist is the marketing site for Kiosist Pvt. Ltd., a company providing 24/7 virtual front-desk / self-service kiosk staffing for hotels across the USA (operations based in Surat, Gujarat, India). The site is a single-language (English, lang="en") Next.js App Router application with no locale routing or translation layer.

Two decisions recur everywhere: (1) almost every page's copy and images are editable from a built-in /admin panel, backed by Supabase, with hard-coded TypeScript defaults as a fallback so the public site keeps working even if Supabase is unreachable or unconfigured; (2) the marketing pages are heavily animated (Framer Motion, a Three.js particle background, Lenis smooth scroll), while /admin is a plain, fast CRUD interface with none of that.

Admin panel

A password-gated CMS at /admin for editing everything the public site reads from Supabase, with no code changes or redeploy needed.

RoutePurpose
/admin/loginSingle-password login (checked against ADMIN_PASSWORD); issues a signed session cookie.
/adminDashboard — new/total inquiry counts, content collection count (8), uploaded media count.
/admin/inquiriesTable of contact + career submissions; mark read/archived, open a submitted résumé.
/admin/contentIndex of the 8 editable content collections.
/admin/content/[collection]Add / edit / delete / drag-reorder items within one collection.
/admin/textEdit the 4 registered freeform text keys (hero subtitles, nav CTA label).
/admin/mediaReplace fixed image slots (logo, career hero, career mascot) and manage reorderable photo galleries.
Auth model: proxy.ts (Next's Proxy/middleware layer) optimistically gates every /admin/* and /api/admin/* route except the login endpoint, redirecting unauthenticated page visits and returning 401 for API calls. Because Proxy alone isn't a full auth boundary, every admin Route Handler and the protected layout independently re-verify the session server-side via requireAdminSession(). Sessions are a jose-signed JWT cookie, keyed by the SESSION_SECRET env var.

Database — Supabase (Postgres)

Defined once in supabase/schema.sql, run manually in the Supabase SQL editor. Four tables, all with RLS enabled and zero policies added on purpose — that leaves them default-deny for the anon/authenticated roles. The Next.js app never uses the anon key; every read and write goes through the service-role key on the server, which bypasses RLS entirely.

TableKey columnsPurpose
inquiriesid uuid pk · type (contact|career) · name · email · phone · company · properties · role · experience · message · resume_path · status (new|read|archived, default new) · created_atEvery contact-form and career-application submission.
content_itemsid uuid pk · collection text · data jsonb · sort_order int · updated_atOne row per item in each of the 8 editable collections (values, faqs, milestones, journey_years, perks, clients, team, roles). data mirrors the matching content/*.ts TS type.
content_textkey text pk · value text · updated_atFreeform editable strings (hero subtitles, nav CTA label), keyed by a dotted slug e.g. home.hero.title.
mediaid uuid pk · slot_key text unique (nullable) · collection text (nullable) · url · storage_path · alt_text · sort_order · created_atUploaded images. Exactly one of slot_key (a fixed swap-in-place image) or collection (a free add/remove/reorder gallery) is set per row.
Storage buckets (created from the Supabase dashboard, not SQL): media — public, serves site images via *.supabase.co/storage/v1/object/public/** (whitelisted in next.config.js image remote patterns); resumes — private, career-application PDFs served only via signed URL.

Content & CMS layer

The pattern that lets /admin edits reach the live site, and lets the site survive Supabase being down.

Collections — lib/cms/collections.ts exposes one typed getter per collection (getValues, getFaqs, getMilestones, getJourneyYears, getPerks, getClients, getTeam, getRoleOptions). Each calls a shared getCollection() that queries content_items filtered by collection name, ordered by sort_order — and falls back to the matching hard-coded default in content/*.ts whenever Supabase is unreachable, misconfigured, or the collection hasn't been seeded yet.
Freeform text — lib/cms/text-keys.ts registers a small, deliberately short list of plain-text fields (headline elements with a styled/colored span stay hard-coded, since one plain string can't represent "some words in a different color"). Registered keys: about.hero.subtitle, career.hero.blurb, contact.hero.subtitle, nav.cta.label. getText(key, fallback) in lib/cms/text.ts reads content_text with the same fallback pattern.
Media — two shapes, both in lib/cms/media.ts. getImageUrl(slotKey, fallback) reads a fixed one-image slot (registered in lib/cms/slots.ts: logo, career.hero, career.mascot) — add an entry there to make another image swappable from /admin/media without touching code. getCultureGallery() reads a free add/remove/reorder gallery collection instead (categories defined in lib/cms/gallery-categories.ts).
